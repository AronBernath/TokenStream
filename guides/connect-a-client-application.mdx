# Connect A Client Application

Use this guide when an application backend or service needs to call TokenStream instead of calling a model provider or retrieval index directly. TokenStream exposes an OpenAI-compatible orchestration endpoint that can route chat completions, enforce pipeline policy, and optionally call retrieval-backed tools.

This page covers the shortest safe connection path: authenticate, discover models, send a first chat completion, and verify the request was routed correctly.

## Prerequisites

Before connecting a client application, confirm the following:

- TokenStream is running locally and the orchestration endpoint is reachable. The local OpenAPI default is `http://localhost:8004`.
- You have a machine API key if service-level authentication is enabled.
- At least one provider and, if you use governed corpora or tool policies, at least one pipeline policy are configured.
- The calling application knows which model identifier to request. Prefixed model IDs such as `provider:model` are supported and are useful when multiple providers expose overlapping model names.

<Warning>
Service-level Bearer authentication is enforced when `ORCHESTRATOR_API_KEYS_JSON` or `ORCHESTRATOR_API_KEY` is configured at runtime. If authentication is enabled, every client request must include `Authorization: Bearer <machine-key>`. In local development, authentication may not be enabled by default.
</Warning>

Machine keys are separate from human administrator accounts. For client integration, create a machine key with the scopes required by the client workload:

| Workload | Scope evidence |
| --- | --- |
| Chat completion | Machine key scopes such as `chat:invoke` |
| Structured retrieval through `/v1/rag/query` | `rag:query` |
| Corpus and ingestion management | Management scopes such as `corpora:read` and `corpora:write` |

<Note>
Do not call `retrieval-api` directly from a normal client application. The normal client boundary is `orchestrator-api`; direct retrieval access is intended for trusted internal clients. Use `/v1/rag/query` when you need deterministic retrieval through the orchestration boundary.
</Note>
